# 局部优化数据流说明

这份文档专门解释当前项目里“局部优化”是怎么完成的。

结论先说：

- 主模型**不直接输出局部增强图**
- 主模型**也不直接输出 mask**
- 主模型做的是：
  - 读取 `mask_tensor[5]`
  - 基于这些 mask 感知局部区域
  - 预测局部参数和局部 gate
- 真正的局部像素修改发生在 `render` 的 `semantic_local` pass 里

---

## 1. 整体链路

```text
                   +-------------------+
reference_image -->|   style encoder   |
                   +-------------------+
                             |
                             v
                   +-------------------+
neutral_preview -->|   scene encoder   |---- scene_features ----+
                   +-------------------+                        |
                                                                |
mask_tensor[5] -------------------------------------------------+
                                                                |
                                                                v
                                                  +--------------------------+
                                                  | masked_average_pool       |
                                                  | 对每个 mask 做局部池化    |
                                                  +--------------------------+
                                                                |
                                                                v
                                                  +--------------------------+
                                                  | mask_mlp / local_fusion  |
                                                  +--------------------------+
                                                                |
                                     +--------------------------+-------------------------+
                                     |                                                    |
                                     v                                                    v
                        +--------------------------+                         +--------------------------+
                        | semantic_head            |                         | gate_head                |
                        | 输出局部参数             |                         | 输出局部 gate            |
                        +--------------------------+                         +--------------------------+
                                     |                                                    |
                                     +--------------------------+-------------------------+
                                                                |
                                                                v
                                   render.render_with_model_outputs(...)
                                                                |
                                                                v
                                                   +-------------------------+

```

## 2. 5 个 mask 在这里分别干什么

| Mask | 在模型里的作用 | 在渲染里的作用 |
| --- | --- | --- |
| `face` | 告诉模型“人脸区域长什么样” | 只在人脸区域应用 face 局部参数 |
| `person` | 告诉模型“人体区域长什么样” | 只在人体区域应用 person 局部参数 |
| `foreground_subject` | 告诉模型“主体区域长什么样” | 只在主体区域应用 foreground 局部参数 |
| `highlight` | 告诉模型高光分布 | 只在高光区域应用 tonal-local 的高光部分 |
| `shadow` | 告诉模型阴影分布 | 只在阴影区域应用 tonal-local 的阴影部分 |

所以它们不是“可有可无的附加信息”，而是局部调整成立的空间锚点。

### 2.1 如果图里没有人脸 / 没有人像怎么办

这里要区分两件事：

- 没有这个对象
- 少了这个通道

在当前项目约定里，正确做法不是“少传一个 mask”，而是：

- `mask_tensor` 仍然保持 `[5, H, W]`
- 对应通道直接传全 0
- 对应 gate 也应该接近 0

例如：

- 没有人脸：
  - `face` mask 全 0
  - `face_gate = 0`
- 没有人像：
  - `person` mask 全 0
  - `person_gate = 0`
- 没有明确主体：
  - `foreground_subject` mask 全 0
  - `foreground_subject_gate = 0`

这样做的好处是：

- tensor 结构永远固定，不会让输入契约变来变去
- 模型仍然知道“这个通道存在，但当前图像里没有对应对象”
- 渲染器会自然退回 identity，不会错误地对不存在的区域做局部增强

一句话说，就是：

- 5 个通道永远都在
- 只是某些通道可能是全 0

## 3. 主模型到底学什么

主模型学的不是“直接生成一个局部润色后的图像”，而是学这两类东西：

### 3.1 局部参数

当前 `semantic_local` 对应的局部参数共有 18 个：

- `face_exposure`
- `face_sat`
- `face_hue_shift`
- `face_warmth`
- `face_soft_clarity`
- `person_exposure`
- `person_sat`
- `person_hue_shift`
- `person_clarity`
- `foreground_subject_hue_shift`
- `foreground_subject_sat`
- `foreground_subject_luma`
- `foreground_subject_exposure`
- `foreground_subject_contrast`
- `foreground_subject_pop`
- `highlight_warmth_local`
- `shadow_tint_local`
- `shadow_desat`

### 3.2 局部 gate

当前局部相关 gate 有 4 个：

- `face_gate`
- `person_gate`
- `foreground_subject_gate`
- `tonal_local_gate`

它们的作用是：

- 参数决定“做什么”
- gate 决定“做多少 / 要不要参与”

---

## 4. 模型里“局部感知”是怎么来的

主模型内部不是把 mask 当普通附加通道直接拼进 RGB，而是走一条更清晰的局部分支：

```text
scene_features
   +
mask_tensor[5]
   |
   v
对每个 mask 做 masked_average_pool
   |
   v
得到 5 个局部区域的 pooled feature
   |
   v
拼接后送入 mask_mlp
   |
   v
得到 z_mask
   |
   v
与 z_ref + z_scene 一起送入 local_fusion
   |
   v
产出 semantic_head 和 gate_head 的输入
```

这意味着：

- 模型知道“画面里有没有脸 / 人 / 主体 / 高光 / 阴影”
- 也知道这些区域在当前 scene feature 里呈现了什么统计特征
- 然后再输出更有针对性的局部参数

---

## 5. 渲染器里“局部执行”是怎么做的

在 `render` 侧，局部处理不是单独画很多图层，而是走固定图形管线里的一个 pass：

```text
neutral image
   |
   v
mask_prep
   |
   v
semantic_local
   |
   +--> face mask + face params + face_gate
   +--> person mask + person params + person_gate
   +--> foreground mask + foreground params + foreground_subject_gate
   +--> highlight mask / shadow mask + tonal params + tonal_local_gate
   |
   v
masked fullscreen shader
   |
   v
输出更新后的图像
```

这里的核心不是“模型自己改像素”，而是：

- 模型给出局部控制量
- 渲染器按 mask 把这些控制量只施加在对应区域

---

## 6. 为什么这样设计是合理的

这种设计比“让模型直接输出一张风格图”更适合你这个项目，因为：

- 你要的是可控审美风格迁移，不是端到端像素生成
- 局部参数仍然落在固定渲染图里，可解释、可调试
- mask 让局部处理有明确空间边界，不容易把整张图搞脏
- gate 让局部模块在不需要时自动退回接近 identity

---

## 7. 这条链路里主模型不做什么

为了避免后面再混淆，下面这些事情不是主模型做的：

- 不输出 `mask[5]`
- 不输出局部润色后的图像
- 不直接改全分辨率像素
- 不决定最终文件格式或色彩空间写盘

主模型只负责：

- 看参考图和当前 neutral preview
- 利用已有的 `mask_tensor[5]`
- 输出 `params[100] + gates[11]`

---

## 8. 对 UniFFI 接口意味着什么

如果后面要给 `render` 做 UniFFI 导出，局部优化这条链的真实边界应该是：

- 原生层准备：
  - `neutral_image`
  - `mask[5]`
  - 主模型输出的 `params[100]`
  - 主模型输出的 `gates[11]`
- Rust render 负责：
  - `mask_prep`
  - `semantic_local`
  - 后续全部固定渲染 pass

也就是说，UniFFI 里不应该把 `mask[5]` 假装成主模型输出，而应该把它视为渲染输入的一部分。
